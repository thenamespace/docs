Find the symptom you're seeing below. Each entry gives the likely cause, a short fix, and the page with the full details.

Before you dig in, rule out the usual suspects:

- The client's network matches the parent name. Use `mode: 'sepolia'` or `isTestnet` for testnet names, and mainnet settings for mainnet names.
- The package version in your project matches the version these docs use.
- API keys and private keys are loaded from server-side environment variables.

## Offchain subnames

### An offchain subname doesn't resolve

**Likely cause:** the parent name isn't using the Namespace resolver, or the app reading the name doesn't support CCIP Read.

1. In the [Namespace App](https://app.namespace.ninja/offchain), open **Offchain**, select the parent name, and open **Resolution**. Click **Update resolver**, then **Configure**, until the status reads **Configured**.
2. Look the name up with [Resolvio](/user-guide/resolvio). If it resolves there, the problem is in the consuming app.
3. Confirm the consuming wallet or library supports CCIP Read. Offchain subnames don't support reverse resolution, so looking up a name from an address won't return them.

See [Configure the resolver](/user-guide/dev-portal#configure-the-resolver).

### Subnames stopped resolving after an ENSv2 upgrade

**Likely cause:** upgrading a name to ENSv2 resets its resolver.

1. Open the name in the Namespace App, go to **Offchain** > **Resolution**, and set the Namespace resolver again with **Update resolver** and **Configure**.
2. Check that the status reads **Configured**.

Your existing subnames and SDK code don't need to change. See [Namespace ENSv2 migration](/overview/ensv2#upgrade-to-ensv2-in-the-namespace-app).

### `401` from the Offchain API

**Likely cause:** the API key is missing, expired, revoked, or scoped to a different parent name. The API returns `401` with "Missing or invalid API key".

1. Check that your server loads the key and sends it. The REST API expects it in the `x-auth-token` header. The SDK takes it as `defaultApiKey` or in `domainApiKeys`.
2. Check the key's scope. A domain-based key only works for the parent name it was created for. An address-based key works for every name the creating wallet owns.
3. If the key has expired or you've lost it, [create a new key](/user-guide/dev-portal#create-an-api-key).

See [API key setup](/developer-guide/sdks/offchain-manager/generate-api-key) and the [API overview](/api-reference/introduction).

### Subname already exists or is unavailable

**Likely cause:** the label is already registered under the parent. Creating it again returns `409` "Subname already exists" from the API.

1. Call `isSubnameAvailable` before `createSubname`.
2. To change an existing subname, call `updateSubname` instead of creating it again.

```typescript
const { isAvailable } = await client.isSubnameAvailable('alice.example.eth');

if (isAvailable) {
  await client.createSubname({ parentName: 'example.eth', label: 'alice' });
} else {
  await client.updateSubname('alice.example.eth', {
    texts: [{ key: 'name', value: 'Alice' }],
  });
}
```

See [Check subname availability](/developer-guide/sdks/offchain-manager/is-subname-available).

### Can't create more subnames under a parent

**Likely cause:** you've reached the limit of 2,000 subnames per parent name.

1. Ask for a higher limit in the [Namespace Builders group](https://t.me/+5FAwyiKOTeswNTIy).

See [Offchain subnames](/user-guide/dev-portal).

## Records

### Records don't show in wallets or apps

**Likely cause:** the record was saved under a different chain or key than the app reads, or the app shows cached data.

1. Fetch the subname with `getSingleSubname` and check the stored records.
2. Check address records use the right [`ChainName`](/developer-guide/sdks/offchain-manager/chainname). To set one EVM address on every supported EVM chain, use [`setDefaultEvmAddress`](/developer-guide/sdks/offchain-manager/set-default-evm-address).
3. Check text record keys match what the app reads, such as `description`. Keys are case-sensitive.

If you read through Resolvio, [clear the name's cache](/api-reference/resolvio/clear-ens-cache) before reading again.

### Creating a subname fails validation

**Likely cause:** the label or address is malformed.

1. Pass only the label in `label` and the parent in `parentName`, not the full subname.
2. Use a complete, valid address for each `ChainName`.
3. Follow [ENSIP-15](https://docs.ens.domains/ensip/15/) normalization for labels.

See [Create or update a subname](/developer-guide/sdks/offchain-manager/create-update-subname).

## Onchain subnames (ENSv2)

### An onchain mint fails or the label can't be minted

**Likely cause:** one of the listing's rules blocks this label or wallet. Onchain subnames are minted on Ethereum (L1) under a name activated in the Namespace App.

Check the listing in [Configure pricing and rules](/user-guide/app#configure-pricing-and-rules):

1. **Price**: type the label into **Price check** to see what it costs. A [reservation](/user-guide/app#reservations) can block the label or give it a custom price.
2. **Who can mint**: with a [whitelist](/user-guide/app#whitelist) in **Gate** mode, only listed wallets can mint. With [token gating](/user-guide/app#token-gated), the wallet must hold the minimum balance of the listed tokens.
3. **When**: minting only works inside the [mint window](/user-guide/app#mint-window), if one is set.

Labels that are already minted show as taken. Pick another label.

### Mint is blocked with "Insufficient funds"

**Likely cause:** the wallet doesn't hold enough of the payment token or ETH. Onchain subnames are paid in USDC or DAI, and network fees are paid in ETH. The ENS Components forms block the transaction with "Insufficient funds" when the wallet can't pay.

1. Add USDC or DAI to cover the price, and pick that token in the mint form.
2. Add ETH to cover network fees.

See [Mint onchain subnames](/developer-guide/sdks/ens-components/mint-subnames).

## ENS Components

### Forms render unstyled

**Likely cause:** the stylesheet isn't imported.

1. Import it once at the root of your app: `import '@thenamespace/ens-components/styles.css';`

See [Import the styles](/developer-guide/sdks/ens-components/installation#import-the-styles).

### Forms throw provider or wallet errors

**Likely cause:** the forms aren't wrapped in the wagmi and React Query providers, a chain is missing from the wagmi config, or the forms render on the server.

1. Wrap your app in `WagmiProvider` and `QueryClientProvider`.
2. Add every chain you use to the wagmi config: `mainnet`, plus `sepolia` if you use `isTestnet`. Minting under an ENSv1 listing can also need Base or Optimism.
3. In Next.js and other SSR frameworks, render the forms and providers in client components (`'use client'`).

Pass `onConnectWallet` to the forms so a disconnected user can connect. See [Install ENS Components](/developer-guide/sdks/ens-components/installation).

### `SubnameMintForm` doesn't work for your parent name

**Likely cause:** the parent has no ENSv2 activation, or it's an ENSv1 listing.

1. [Activate the name](/user-guide/app#activate-your-ens-name) in the Namespace App.
2. For a parent listed before ENSv2, pass `version={1}`.

See [Mint under an old Namespace listing](/developer-guide/sdks/ens-components/mint-subnames#mint-under-an-old-namespace-listing).

### `OffchainSubnameForm` shows success but no subname is created

**Likely cause:** the form only reads from Namespace. It never writes the subname itself.

1. Pass `onSubnameCreated` and `onSubnameUpdated` callbacks that send the subname to your server.
2. On your server, write it with an Offchain Manager client that holds the API key.

See [Create offchain subnames](/developer-guide/sdks/ens-components/offchain-subnames).

## Rate limits

### Requests fail intermittently or get rate limited

**Likely cause:** you're using a shared public RPC endpoint. `http()` with no URL in wagmi uses the chain's public RPC, which is rate limited.

1. Pass your own RPC URL for each chain in production.
2. Retry transient failures, such as `5xx` responses, with bounded exponential backoff.

See [Set up providers](/developer-guide/sdks/ens-components/installation#set-up-providers).

## ENSv1 listings (deprecated)

<Warning>
  Mint Manager, Indexer Manager, and the Mint API are deprecated. They only work with onchain listings on ENSv1 names. For new names, use [ENSv2 onchain subnames](/user-guide/app) and [`SubnameMintForm`](/developer-guide/sdks/ens-components/mint-subnames).
</Warning>

### `checkName` returns `taken` or `blocked`

`taken` means the label is registered, so offer a different one. `blocked` means the label is free but this wallet can't mint it. Read `reasons`, such as `MINTER_NOT_WHITELISTED`, `MINTER_NOT_TOKEN_OWNER`, or `LISTING_EXPIRED`. See [Check a name before you mint](/developer-guide/sdks/mint-manager/check-name).

### Mint Manager throws `MintManagerError`

Branch on `error.code`:

- `RPC_ERROR`: a registry read failed, so the name's status is unknown. Retry, and pass your own endpoints in `customRpcUrls`.
- `LISTING_NOT_FOUND`: no listing exists for the parent on this network. Check `isTestnet` and the spelling.
- `PRICE_EXCEEDS_MAX`: the quote went over your `maxValue` and nothing was submitted. Re-quote, then raise the cap or show the new price.
- `SIGNATURE_EXPIRED`: the mint authorization expired. Call `prepareMint` again and submit promptly.

See [Error handling](/developer-guide/sdks/mint-manager/errors) for every code.
