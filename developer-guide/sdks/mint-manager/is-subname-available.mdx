`isL1SubnameAvailable` and `isL2SubnameAvailable` report raw registry ownership. Use the method that matches the parent name's listing: `isL1SubnameAvailable` for Ethereum, or `isL2SubnameAvailable` for an L2 chain.

<Warning>
  Both methods are deprecated in favor of [`checkName`](/developer-guide/sdks/mint-manager/check-name), which reports registry ownership **and** whether the minter is permitted to mint, and derives the chain from the listing. A `true` from these methods can still be followed by a failed mint, because an allowlist, a reservation, or an expired listing is invisible to the registry. Reach for them only when you want ownership alone and have no minter address in hand.
</Warning>

## Check availability on Ethereum

Use `isL1SubnameAvailable` for a parent name listed on Ethereum mainnet:

```typescript
const isAvailable = await mintClient.isL1SubnameAvailable(
  'alice.example.eth',
);
```

## Check availability on L2 chains

Use `isL2SubnameAvailable` with the target chain ID. This example checks Base:

```typescript
import { base } from 'viem/chains';

const isAvailable = await mintClient.isL2SubnameAvailable(
  'alice.example.eth',
  base.id,
);
```

## Handle lookup failures

Both methods throw `RPC_ERROR` when the registry cannot be reached. A failed lookup is not an answer about the name, and reporting it as "taken" tells a user a free name is gone.

```typescript
import { MintManagerError } from '@thenamespace/mint-manager';

try {
  const isAvailable = await mintClient.isL1SubnameAvailable('alice.example.eth');
} catch (error) {
  if (error instanceof MintManagerError && error.code === 'RPC_ERROR') {
    // Temporary lookup failure. Offer a retry rather than a result.
  }
}
```

Because these methods read from an RPC endpoint, supply your own through `customRpcUrls` for anything user facing. The default is a shared public endpoint and is rate limited.
