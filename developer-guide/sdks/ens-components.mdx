`@thenamespace/ens-components` is a React library of complete ENS flows. Each form handles input, validation, pricing, wallet prompts, and the success screen, so you add a flow by rendering one component. The forms read the wallet from wagmi and send transactions with viem.

The current major version is 3. Onchain flows run on ENSv2 by default, on Ethereum mainnet or Sepolia.

## Choose a component

| You want to | Use | Page |
| --- | --- | --- |
| Register a `.eth` name | `EnsNameRegistrationForm` | [Register names](/developer-guide/sdks/ens-components/register-names) |
| Renew a `.eth` name | `NameRenewForm` | [Renew names](/developer-guide/sdks/ens-components/renew-names) |
| Edit records on a name the user owns | `EnsRecordsForm` | [Edit records](/developer-guide/sdks/ens-components/edit-records) |
| Collect records in your own flow, without a transaction | `SelectRecordsForm` | [Edit records](/developer-guide/sdks/ens-components/edit-records#collect-records-without-a-transaction) |
| Mint an onchain subname | `SubnameMintForm` | [Mint subnames](/developer-guide/sdks/ens-components/mint-subnames) |
| Renew an onchain subname | `SubnameRenewForm` | [Renew subnames](/developer-guide/sdks/ens-components/renew-subnames) |
| Create or update a gasless offchain subname | `OffchainSubnameForm` | [Offchain subnames](/developer-guide/sdks/ens-components/offchain-subnames) |
| Show progress for your own transaction | `TransactionProgress`, `TransactionModal` | [Transaction progress](/developer-guide/sdks/ens-components/transaction-progress) |

The package also exports hooks and ENSv2 helpers for custom flows. See [Hooks and helpers](/developer-guide/sdks/ens-components/hooks).

## Quick example

After you [install the package and set up providers](/developer-guide/sdks/ens-components/installation), render a form:

```tsx
'use client';

import { EnsNameRegistrationForm } from '@thenamespace/ens-components';

export function RegisterName() {
  return (
    <EnsNameRegistrationForm
      onRegistrationSuccess={(result) => {
        console.log(`Registered until ${result.expiryDate}`);
      }}
    />
  );
}
```

## How ENSv2 works in the forms

These rules apply to registration, renewal, subname minting, and subname renewal.

- **Networks:** Ethereum mainnet by default, or Sepolia when you pass `isTestnet`.
- **Payment:** `.eth` registration and renewal are paid in USDC or DAI. Subname mints and renewals are paid in a token the parent's activation accepts: ETH, USDC, or DAI on mainnet, and ETH or USDC on Sepolia. The user picks the token inside the form. Network fees are always paid in ETH.
- **Wallet prompts:** Wallets that support EIP-5792 atomic batching confirm each step in one prompt. Other wallets get one prompt per call, for example a token approval before the payment. The forms handle approvals, so don't add your own.
- **Balances:** When the wallet holds too little of the chosen token, or too little ETH for gas, the form shows "Insufficient funds" and blocks the transaction.

The one ENSv1 flow still in use is minting under a parent on an old Namespace listing. Pass `version={1}` to `SubnameMintForm` for those parents. See [Mint under an old Namespace listing](/developer-guide/sdks/ens-components/mint-subnames#mint-under-an-old-namespace-listing).
