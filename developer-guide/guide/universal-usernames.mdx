Add one endpoint to your API, connect it to your `.eth` name, and every username in your app resolves as an ENS name: `happy` becomes `happy.brand.eth`.

## How it works

<FlowExplainer />

When a wallet looks up `happy.brand.eth`, the Namespace gateway calls `GET {your endpoint}/happy`, turns your JSON into ENS records and signs the answer. Your database stays the source of truth.

## Prerequisites

- A second-level `.eth` name, such as `brand.eth`, owned by a wallet you control
- A public HTTPS API you can add a route to

<Steps>
  <Step title="Add the endpoint">

Add a route that takes a username and returns its profile as JSON. For `GET https://api.brand.example/ens/happy`:

```json
{
  "version": 1,
  "username": "happy",
  "texts": {
    "name": "Happy",
    "avatar": "https://cdn.brand.example/avatars/happy.png",
    "com.twitter": "happy"
  },
  "addresses": {
    "2147483648": "0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045",
    "0": "bc1qar0srrr7xfkvy5l643lydnw9re59gtzzwf5mdq",
    "501": "9WzDXwBbmkg8ZTbNMqUxvQRAyrZzDsGYdLVL9zYtAWWM"
  }
}
```

- Return `404` for users that don't exist.
- `username` must match the requested username exactly. It arrives URL-encoded, so decode it first.
- Respond with `Content-Type: application/json`, uncompressed, under 256 KiB and within 5 seconds. Redirects aren't followed.
- `texts` and `addresses` are required. Use `{}` when empty.

<Warning>
Everything you return is public. Only include what your users have chosen to share.
</Warning>

  </Step>
  <Step title="Key addresses by coin type">

Each key in `addresses` is an ENS coin type, written as a decimal string. Values are addresses in their usual format.

| Chain | Coin type |
| --- | --- |
| Any EVM chain (default) | `2147483648` |
| Ethereum | `60` |
| Other EVM chains | `2147483648 + chainId`. Base (8453) is `2147492101` |
| Bitcoin | `0` |
| Solana | `501` |

If a user has one address on every EVM chain, set only `2147483648`. Ethereum and every other EVM chain fall back to it. To compute a chain's coin type, use viem:

```ts
import { toCoinType } from 'viem';

String(toCoinType(8453)); // "2147492101" (Base)
```

For other chains, look up the coin type in [ENSIP-9](https://docs.ens.domains/ensip/9).

  </Step>
  <Step title="Connect it in the Namespace App">

1. Open [Universal Usernames](https://app.namespace.ninja/universal-usernames) with the wallet that owns `brand.eth` and pick the name.
2. Enter your endpoint URL, for example `https://api.brand.example/ens`. Add a bearer token if your API needs one. Namespace sends it as `Authorization: Bearer <token>`.
3. Save, then send the transaction to switch the name to Universal Usernames.

<Warning>
After the switch, subnames you created with Namespace's offchain subnames under `brand.eth` stop resolving.
</Warning>

  </Step>
  <Step title="Test it">

Call your endpoint directly:

```bash
curl -i https://api.brand.example/ens/happy
```

Then resolve the name like any ENS name:

```ts
import { createPublicClient, http } from 'viem';
import { mainnet } from 'viem/chains';

const client = createPublicClient({ chain: mainnet, transport: http(process.env.ETH_RPC_URL) });

console.log(await client.getEnsAddress({ name: 'happy.brand.eth' }));
```

Changes to a profile show up within 60 seconds.

  </Step>
</Steps>

## If a name doesn't resolve

The gateway answers `502` with a reason such as `USERNAME_MISMATCH`, `CONTENT_TYPE_INVALID` or `HTTP_TIMEOUT`. viem's error includes the gateway URL. Open it with `curl` to read the reason.
