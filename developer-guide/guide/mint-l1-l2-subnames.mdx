This guide shows how to mint an onchain subname under an ENS name activated in the Namespace App. The Mint Manager SDK selects the correct mint contract for Ethereum or the parent listing's L2 chain; your Viem clients submit the resulting transaction on that chain.

The complete example uses Base. The SDK derives the chain from the parent listing, so the same code mints an Ethereum listing without change.

## Prerequisites

- Node.js 22 and npm
- TypeScript experience
- An ENS name activated and listed in the [Namespace App](/user-guide/app#activate-your-ens-name)
- A wallet with enough native currency for the mint price and gas
- An RPC endpoint for the chain on which you will mint

<Warning>
  Use a dedicated development wallet and a testnet listing while testing. Never expose a wallet private key in browser code or commit it to source control.
</Warning>

<Steps>
  <Step title="1. Activate your ENS name">

    Before you can mint subnames, your parent ENS name must be activated on the Namespace platform. This is a prerequisite for all subname minting operations.

    <Card title="How to activate an ENS name" icon="hat-wizard" horizontal href="/user-guide/app#activate-your-ens-name">
      See the step-by-step guide on how to activate an ENS name.
    </Card>
  </Step>

  <Step title="2. Install the dependencies">

    Install the package versions used by this documentation:

    <CodeGroup>
      ```bash npm
      npm install @thenamespace/mint-manager@2.0.0 viem dotenv
      ```

      ```bash yarn
      yarn add @thenamespace/mint-manager@2.0.0 viem dotenv
      ```
    </CodeGroup>
  </Step>

  <Step title="3. Configure the clients">

    Add the RPC endpoint and private key to `.env`:

    ```bash .env
    BASE_RPC_URL=https://your-base-rpc.example
    WALLET_PRIVATE_KEY=0xYOUR_PRIVATE_KEY
    ```

    Create the Mint Manager SDK client and Viem clients:

    ```typescript clients.ts
    import 'dotenv/config';
    import { createMintClient } from '@thenamespace/mint-manager';
    import {
      createPublicClient,
      createWalletClient,
      http,
      type Hex,
    } from 'viem';
    import { privateKeyToAccount } from 'viem/accounts';
    import { base } from 'viem/chains';

    const rpcUrl = process.env.BASE_RPC_URL;
    const privateKey = process.env.WALLET_PRIVATE_KEY as Hex | undefined;

    if (!rpcUrl) throw new Error('Missing BASE_RPC_URL');
    if (!privateKey) throw new Error('Missing WALLET_PRIVATE_KEY');

    export const account = privateKeyToAccount(privateKey);
    export const mintClient = createMintClient({
      mintSource: 'my-app',
      // Share one endpoint between the SDK's reads and your viem clients, so
      // the availability check and the transaction cannot disagree about
      // chain state. The SDK default is shared and rate limited.
      customRpcUrls: { [base.id]: rpcUrl },
    });
    export const publicClient = createPublicClient({
      chain: base,
      transport: http(rpcUrl),
    });
    export const walletClient = createWalletClient({
      account,
      chain: base,
      transport: http(rpcUrl),
    });
    ```

    <Note>
      To use testnet listings and Namespace staging services, initialize the Mint Manager SDK with `createMintClient({ isTestnet: true, mintSource: 'my-app' })` and configure Viem clients for the matching testnet chain.
    </Note>
  </Step>

  <Step title="4. Check the name">

    `checkName` answers both questions a mint needs in one call: is the name free, and may this wallet mint it. Pass the whole subname; the SDK normalizes it, resolves the listing, and works out the chain itself.

    ```typescript check.ts
    import { account, mintClient } from './clients';

    export const fullName = 'alice.example.eth';

    export async function checkSubname() {
      const check = await mintClient.checkName(fullName, {
        minterAddress: account.address,
        expiryInYears: 1,
      });

      if (check.status !== 'available') {
        // The advice depends on the obstacle. A taken or reserved label means
        // try another one; an allowlist or token gate fails the same way for
        // every label, so sending the user back to the name field wastes
        // their time.
        throw new Error(
          `${fullName} is ${check.status}: ${check.reasons.join(', ')}`,
        );
      }

      console.log({
        priceEth: check.estimatedPriceEth,
        feeEth: check.estimatedFeeEth,
        chainId: check.chainId,
      });

      return check;
    }
    ```

    The result is a discriminated union on `status`, so the price fields exist only on the `available` branch. See [Check a name](/developer-guide/sdks/mint-manager/check-name) for every status and the full table of refusal reasons.
  </Step>

  <Step title="5. Generate transaction parameters">

    Pass the check result to `prepareMint`. The listing is already resolved, so nothing is fetched twice. Add optional text and address records to apply them in the same transaction as the mint:

    ```typescript transaction.ts
    import { parseEther } from 'viem';
    import { ChainName } from '@thenamespace/mint-manager';
    import { account, mintClient } from './clients';
    import { checkSubname } from './check';

    export async function getTransaction() {
      const check = await checkSubname();

      // Cap what the signed quote may charge. Prices are quoted per request
      // and can move between the quote and the signature; without this, the
      // new price is simply charged.
      const quoted = parseEther(
        (check.estimatedPriceEth + check.estimatedFeeEth).toFixed(18),
      );

      return mintClient.prepareMint(check, {
        minterAddress: account.address,
        owner: account.address,
        expiryInYears: 1,
        maxValue: quoted,
        records: {
          texts: [
            { key: 'description', value: 'Minted with Namespace' },
          ],
          addresses: [
            { chain: ChainName.Ethereum, value: account.address },
          ],
        },
      });
    }
    ```

    The SDK uses the parent listing to return the appropriate contract, ABI, arguments, and transaction value for Ethereum or the listing's L2 chain.
  </Step>

  <Step title="6. Simulate and send the transaction">

    Simulate first so contract errors are surfaced before the wallet sends the transaction:

    ```typescript mint.ts
    import { MintManagerError } from '@thenamespace/mint-manager';
    import {
      account,
      publicClient,
      walletClient,
    } from './clients';
    import { getTransaction } from './transaction';

    async function main() {
      const transaction = await getTransaction();

      const { request } = await publicClient.simulateContract({
        account,
        address: transaction.contractAddress,
        abi: transaction.abi,
        functionName: transaction.functionName,
        args: transaction.args,
        value: transaction.value,
      });

      const hash = await walletClient.writeContract(request);
      console.log(`Submitted transaction: ${hash}`);
    }

    main().catch((error: unknown) => {
      if (error instanceof MintManagerError) {
        // Codes are stable across minor versions; match on them rather than
        // on message text.
        console.error(error.code, error.message, error.details);
        process.exitCode = 1;
        return;
      }

      console.error(error);
      process.exitCode = 1;
    });
    ```

    Wait for a receipt before showing the subname as confirmed in your product.
  </Step>
</Steps>

## Troubleshooting

- If `checkName` returns `blocked`, read `reasons`. A minter gate fails identically for every label, so prompt for a different wallet rather than a different name.
- If it returns `taken`, choose another label; do not submit the transaction.
- If a call throws `RPC_ERROR`, the name's status is unknown rather than unavailable. Retry, and set `customRpcUrls` to your own endpoints.
- If `prepareMint` throws `PRICE_EXCEEDS_MAX`, the price moved past your cap. Re-run `checkName` and confirm the new price before retrying.
- If it throws `SIGNATURE_EXPIRED`, the authorization aged out. Call `prepareMint` again and submit promptly.
- If simulation fails, confirm the wallet and public clients use the chain reported in `check.chainId`.

See [Error handling](/developer-guide/sdks/mint-manager/errors) for every code.

See [Troubleshooting](/developer-guide/troubleshooting) for authentication, resolver, network, and transaction diagnostics.
